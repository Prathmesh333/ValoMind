## Run and resume

1. Open the notebook in Colab and select a T4 GPU. Only CUDA device 0 is used.
2. Run all cells and mount Drive. Defaults scan full broadcasts at ten-second
   intervals. There is no `END_SECONDS=120` preview limit in this workflow.
3. The queue processes one source at a time in chunks of 100 new probes. A
   90-minute session budget is checked between chunks. Downloads or an individual
   chunk may extend beyond the budget. Five broadcasts are not guaranteed to
   finish in one free session; no completion-time or speed benchmark is claimed.
4. Run the queue cell again to continue. After a disconnect, rerun setup/config
   with the same RUN_NAME, source list, worker and OCR package versions. Changed
   configurations require a new run root rather than mixing incompatible jobs.
5. Run the export cell for a partial/completed ZIP, saved under Drive's
   `ValoMind/exports/`. Drive also retains original per-job CSVs and SQLite state.

The default persistent root is `/content/drive/MyDrive/ValoMind/<RUN_NAME>`.
Temporary videos use `/content/valomind_media`, require at least 30 GiB free before
download, and are removed only after their source finishes. Source metadata is
copied into the persistent job first. Private Drive archives, cookies and outputs
are never removed by this cleanup. A fresh runtime may need to redownload the
current incomplete video, but committed OCR frames are reused.

Kaggle uses `/kaggle/working/ValoMind` for outputs and `/kaggle/temp/valomind_media`
for temporary media. Kaggle working storage is not durable across fresh sessions:
save the version/outputs and restore the entire run folder, including SQLite,
before resuming. Do not have two notebooks write the same queue root. Separate
notebooks can use disjoint source subsets and distinct RUN_NAME values, subject to
provider quotas; no account rotation or quota bypass is implemented.

## Data produced and current limits

- `observations.csv`: raw OCR/detector proposals with provenance. No custom detector
  or portrait classifier weights are enabled by default.
- `segments.csv`, `round_context.csv`: sampled HUD/broadcast and phase proposals,
  including unknowns. Missing OCR or unsupported graphics remain reviewable.
- `segment_review/`: up to 240 review frames distributed over each entire source,
  including filler, replay and uncertain states. These support scene labeling.
- `unlabeled_samples.csv`, `minimap_candidates/`: image references, source grouping,
  proposed context and uncalibrated upper-left crops. A crop is not a detected
  minimap, marker location, player identity or statement about player knowledge.
- `roster_observations.csv`: may be empty on these new sources. The previous
  source-specific 100T/VIT aliases are deliberately not reused. Supply a reviewed
  per-source catalog and verify the layout before interpreting player/agent pairs.
- Queue/progress JSON, per-job SQLite, environment and source metadata support
  continuation and diagnosis. Combined exports are generated from recorded chunks.

Default sampling uses checked frame-index seeking to avoid decoding every frame
between probes. Source timestamps are `frame_index / reported_fps` estimates, not
native-PTS action measurements. The decoder must report the requested frame;
unexpected seeking fails visibly. Completed frame records are skipped without
decoding them again. Completed immutable source hashes are cached by path/size/mtime
within a session to avoid rehashing a multi-GB video on every chunk.

Native-PTS dense windows remain optional (`DENSE_WINDOWS_PER_VIDEO=0` by default).
Enabling one/two windows saves two-second frame sequences near sparse gameplay
proposals before temporary media cleanup. These require full visual continuity,
identity and visibility review. No reaction time is inferred from sparse probes.

No ViT training, psychological inference, automatic human approval, verified player
database, agent recognition or minimap tracking is claimed. All identities missing
from reviewed catalogs stay unknown. Source permissions retain their existing
unconfirmed status; raw outputs are private and excluded from Git.

## YouTube access errors

The queue validates a supported JS runtime but cannot guarantee YouTube access
from cloud IPs. Sign-in/bot errors stop the queue. There is no automatic retry
across five sources, proxy rotation or account rotation. Set an own-session
Netscape `COOKIE_FILE` outside both export/media roots, or restore a matching
full-source archive through `SOURCE_ARCHIVES`. The old one-hour highlight ZIP
cannot restore these new broadcasts. Enable `RETRY_ERRORS=True` only after fixing
the actual problem, then return it to False.

Cookie files and full source media are excluded from export snapshots. Do not
paste credentials into notebook source, chat or Git. A raw movie without matching
metadata is not silently assigned to a different YouTube ID.

## Validation

Tests cover source validation, blocked acquisition, persistent queue completion,
configuration isolation, bounded seek chunks and skipping committed frames. All
generated notebook code cells are syntax checked. Cloud GPU inference and complete
multi-hour downloads are not exercised by these local tests; free T4 throughput
and the unfamiliar broadcast layout remain to be checked in Colab.
